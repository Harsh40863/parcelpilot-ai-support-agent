# AI Tool Usage

I used **Antigravity** (AI coding agent) as an implementation tool, the way I'd use any pair-programmer — I know this stack (LangChain/LangGraph, FastAPI-adjacent patterns, FAISS, MongoDB, Streamlit) and made every architecture and design decision myself: which tools to expose, how to enforce access control at the data layer rather than through prompting, the source-priority rules for conflict resolution, the human-in-the-loop gate for state-changing actions, and every trade-off documented in the Architecture Note. Antigravity wrote the code to my specification and ran the tests; I reviewed every implementation plan before approving it, and instructed specific edits when something wasn't right — for example, correcting checkpointer setup after a `TypeError`, rejecting a proposed retry pattern that broke tool binding, and directing the fix for a hallucinated escalation confirmation once I traced it to root cause myself by checking `escalations.json` directly rather than trusting the reported test output.

I did not accept "tests passed" claims at face value. On two occasions, an automated test report described something as working when it wasn't — a fabricated escalation success message with no corresponding tool call, and a login failure from an environment secret that had silently failed to save on the deployment platform. Both were caught because I independently re-tested live on the deployed app, diagnosed the actual cause, and directed the specific fix. I also made the call to revert a session-persistence feature attempt after three fix rounds still left a minor UX flash, rather than continuing to iterate against a hard deadline — a judgment call about scope and risk, not a technical one Antigravity made for me.
